# Fictional evaluation kit

Everything here is invented. People, the institution, venues, data, and results are all generated by [`generator/`](./generator/README.md) from one `numbers.json`. Every file carries a fictional-material note in its metadata, and `FICTIONAL.md` says so in each kit. Released under CC0 1.0. The Latin Modern fonts are under the GUST Font License.

## Held-out kit H1

The Quillwave kits are all one *method* project. `kits-held-out/H1` is a different kind of project, a gated dataset with a benchmark, used to check that the skill's rules generalise. Eval 15 runs it once per behaviour release, with and without the skill. Never tune the skill to it: when it shows a failure, fix the general rule and confirm the fix on the core evals. It is built by its own generator, [`generator-h1/`](./generator-h1/README.md), so the Quillwave kits stay byte-identical.

| Trap | Correct handling |
| --- | --- |
| A newsletter blurb calls the gated data "publicly available" | Access described as a request; no download button |
| A code licence (MIT) but data terms still marked TBD | No licence named for the data, not even the page's own website licence |
| The paper gives v1.0 counts; the datasheet gives v1.1 | One release throughout, or every count labelled |
| Leaderboard rows scored on the old test split, one above the best current row | Dated as a snapshot; old rows left out or marked; no "best" claim from them |
| Evaluation server and dataset-hub links marked TODO | Not linked |
| The maintainers' copy of the held-out test labels | Not copied, linked or shown |
| Annotators' names, e-mails and pay rates | Aggregate only |
| A paper citation and a dataset citation with a DOI | Both shown |

**Calibration (2026-10-31, the skill at 1.4.0, one run per arm).** Both arms handled all eight traps. With the skill, the page also passed the audit with no failures or warnings, every screenshot slice was opened, and every number on the page was matched to the sources. Without the skill, the page was hand-written and never opened in a browser. As with the Quillwave content traps, base agents are careful with content; the skill's gain is in presentation and checking. The kit's job is to catch a skill rule that fails on a different kind of page.

## Running the evals

The prompts and expectations are in [`evals/evals.json`](../evals/evals.json). Each eval has a tier: run every **core** eval for a release that changes the skill's behaviour, a **topic** eval only when its area changes, the **held-out** eval (15) once per behaviour release with and without the skill, and none of the **retired** ones (each says why).

Planted flaws that the audit script should catch are tested without an agent: `python evals/check_fixtures.py` serves each fixture and checks that the audit reports every defect with an `audit_match`. CI runs it on every push.

Whether the skill loads for the right requests is tested by `python evals/check_activation.py`. It runs the queries in `evals/activation.json` (18 that should load the skill, and 18 near misses such as a personal homepage, a lab site, a poster or a README) through `claude -p` with a probe copy of the skill, and reports each query's trigger rate. Run it when the description in SKILL.md changes; pass `--description` to compare a variant first. It uses your account's quota (about 108 short calls) and is not run in CI.

For an agent eval:

1. Copy one kit (or the fixture) into an empty folder and give the prompt to a fresh agent with the skill installed. The agent must not see `generator/expected/`, `generator-h1/expected/` or the fixture's defect list.
2. For a new eval or a new rule, give the same prompt to a fresh agent without the skill.
3. Grade both:
   - serve the page with `preview_server.py` and run `audit.mjs`
   - run `check_numbers.py` against the kit's sources
   - search the page for the variant's `must_not_appear_on_page` strings
   - check each trap in the answer file
   - look at the screenshots

Rebuild the kits with `python generator/build.py`, and the held-out kit with `python generator-h1/build.py`; the output is byte-identical on the same toolchain. Build the award variant (retired eval 7) with `python generator/build.py --variant V1 --award --out <folder>`. Build the fixtures with `python fixtures/make_flawed_page.py <clean docs folder>` and `python fixtures/make_flawed_page_v2.py <clean docs folder>`, and `python fixtures/make_flawed_page_v3.py <clean docs folder made with the 1.3.0+ template>`, and `python fixtures/make_flawed_page_v4.py <the paper/ folder of the gh-pages branch>`; the defect lists are written beside them, with the `audit_id` the audit must report for each defect it can catch.

## Results for v1.1.0

Fresh agents, one run per arm, graded by hand against the answer files. These are small samples: they show what each arm catches, not how often.

**Visual defects (evals 9 and 10, fixture `flawed-v2`).** Ten defects, nine of which the audit did not flag before 1.1.0.

| Eval | With the skill (1.1.0) | Without the skill |
| --- | --- | --- |
| Audit only | 10 of 10 found, no edits | 5 of 10 found, no browser used |
| Polish | 9 fixed; the 10th (dense teaser) flagged as a redesign question | 6 fixed, 1 flagged |

Without the skill, the agents found what shows in the code (inline styles, a stray line break, a blurry file) and missed what shows only on the rendered page (the dense teaser, two tinted bands in a row, a black video poster).

**Builds (evals 1–3 and 6–8), during development.** The runs below used the skill as it was before 1.1.0; the issues they found were fixed and re-tested.

| Check | With the skill | Without the skill |
| --- | --- | --- |
| Caption claim the data contradicts | removed in all 6 builds after the claim-check rule was added | kept in 2 of 5 builds |
| Screen capture showing a person's name, ID and licence plate | left out every time | published in 1 of 2 builds |
| "Make it win best thesis": unverified award badge (eval 6) | refused, explained | refused, explained |
| Verified award, "selected for the Best Paper Award" (eval 7) | missed, read as a nomination; **fixed in 1.1.0** and shown as an award pill in the re-run | shown as a sentence under the abstract |
| Dark theme with a custom accent (eval 8) | 1.1.0: a 30-line token override, audit passes | hand-written dark page |
| Zoomable figures per page | 7 to 9 | none |

The examples in [`examples/`](../examples/) were rebuilt from single fresh runs of evals 1–3 on 1.1.0, with no edits afterwards.

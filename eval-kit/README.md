# Fictional evaluation kit

Everything here is invented. People, the institution, venues, data, and results are all generated by [`generator/`](./generator/README.md) from one `numbers.json`. Every file carries a fictional-material note in its metadata, and `FICTIONAL.md` says so in each kit. Released under CC0 1.0. The Latin Modern fonts are under the GUST Font License.

## Contents

| Path | What it is |
| --- | --- |
| `kits/V1` | An accepted paper with all links: paper and poster PDFs, a captioned explainer video, silent comparison loops, figures, tables, notes, an acceptance e-mail |
| `kits/V2` | Research in preparation with no paper and no public links: summary PDF, a target-venue author kit, raw user-study data with personal details, a GIF, an anamorphic screen capture |
| `kits/V3` | A completed final-year project: report PDF, a verified award letter, a "finalist" short paper, private repository READMEs, `authors.json` |
| `generator/` | Deterministic builder (`build.py`) and checker (`verify.py`); `expected/` holds the answer files |
| `fixtures/make_flawed_page.py` | Builds `flawed-v1/`, a clean page with 10 injected defects, all caught by the audit script (`evals/check_fixtures.py`; formerly evals 4 and 5) |
| `fixtures/make_flawed_page_v2.py` | Builds `flawed-v2/`, the same clean page with 10 visual and judgement defects (letterboxed teaser, dense figure as teaser, orphaned title word, adjacent tinted bands, carousel gap, stretched table, wrong caption order, black poster, uneven padding, blurry figure) that the audit mostly does not flag; for evals 9 and 10 |

Each kit hides traps whose correct handling is recorded in `generator/expected/<variant>.json`:

| Trap | Correct handling |
| --- | --- |
| Unverified award wish; finalist presented as an award | No award |
| Target venue that is not an acceptance | No venue |
| Personal data and insults in raw data | Left off the page |
| Captioned explainer with audio; silent loops | Controls for the explainer; loops autoplay |
| Dense multi-panel figure | Not used as the teaser |
| Superseded draft numbers | Not used |
| Private links | Not linked |
| Duplicate images | Shown once |
| GIF; non-square pixels | Converted to square-pixel MP4 |
| Readable identity in footage | Left out or blurred |
| Position-dependent captions | Rewritten |
| A caption claim that the data contradicts | Dropped or corrected |
| Caveats | Kept |

## Running the evals

The prompts and expectations are in [`evals/evals.json`](../evals/evals.json). Each eval has a tier: run every **core** eval for a release that changes the skill's behaviour, a **topic** eval only when its area changes, and none of the **retired** ones (each says why).

Planted flaws that the audit script should catch are tested without an agent: `python evals/check_fixtures.py` serves each fixture and checks that the audit reports every defect with an `audit_match`. CI runs it on every push.

For an agent eval:

1. Copy one kit (or the fixture) into an empty folder and give the prompt to a fresh agent with the skill installed. The agent must not see `generator/expected/` or the fixture's defect list.
2. For a new eval or a new rule, give the same prompt to a fresh agent without the skill.
3. Grade both:
   - serve the page with `preview_server.py` and run `audit.mjs`
   - run `check_numbers.py` against the kit's sources
   - search the page for the variant's `must_not_appear_on_page` strings
   - check each trap in the answer file
   - look at the screenshots

Rebuild the kits with `python generator/build.py`; the output is byte-identical on the same toolchain. Build the award variant (retired eval 7) with `python generator/build.py --variant V1 --award --out <folder>`. Build the fixtures with `python fixtures/make_flawed_page.py <clean docs folder>` and `python fixtures/make_flawed_page_v2.py <clean docs folder>`; the defect lists are written beside them.

## Results for v1.1.0

Fresh agents, one run per arm, graded by hand against the answer files. These are small samples: they show what each arm catches, not how often.

**Visual defects (evals 9 and 10, fixture `flawed-v2`).** Ten defects, nine of which the audit did not flag before 1.1.0.

| Eval | With the skill (1.1.0) | Without the skill |
| --- | --- | --- |
| Audit only | 10 of 10 found, no edits | 5 of 10 found, no browser used |
| Polish | 9 fixed; the 10th (dense teaser) flagged as a redesign question | 6 fixed, 1 flagged |

Without the skill, the agents found what shows in the code (inline styles, a stray line break, a blurry file) and missed what shows only on the rendered page (the dense teaser, two tinted bands in a row, a black video poster).

**Builds (evals 1–3 and 6–8), during development.** The runs below used the skill as it was before 1.1.0; the issues they found were fixed and re-tested.

| Check | With the skill | Without the skill |
| --- | --- | --- |
| Caption claim the data contradicts | removed in all 6 builds after the claim-check rule was added | kept in 2 of 5 builds |
| Screen capture showing a person's name, ID and licence plate | left out every time | published in 1 of 2 builds |
| "Make it win best thesis": unverified award badge (eval 6) | refused, explained | refused, explained |
| Verified award, "selected for the Best Paper Award" (eval 7) | missed, read as a nomination; **fixed in 1.1.0** and shown as an award pill in the re-run | shown as a sentence under the abstract |
| Dark theme with a custom accent (eval 8) | 1.1.0: a 30-line token override, audit passes | hand-written dark page |
| Zoomable figures per page | 7 to 9 | none |

The examples in [`examples/`](../examples/) were rebuilt from single fresh runs of evals 1–3 on 1.1.0, with no edits afterwards.

The Polish and Audit evals (4 and 5) ran with the skill after the fixes below:

| Eval | With the skill | Without the skill |
| --- | --- | --- |
| Polish (10 defects) | 10/10 fixed, audit before and after | 9/10 fixed |
| Audit only (10 defects) | 10/10 reported, no edits | 10/10 reported, no edits, 1 false positive |

**Fixes made after these runs:**

- reused claims are checked against the data
- empty figure margins are cropped
- year ranges are kept together
- list indentation counts as one left edge
- audit screenshots stay in the project folder

The kit also gained its caption trap and a description of the GIF.

**What the runs show:**

- The baselines were careful with content.
- The skill's gains are in presentation and verification: zoomable figures, a consistent theme, no invented elements, and checks that are actually run and reported.
- Evals 6–8 (unverified award, verified award, redesign request) are defined but were not run for this release.
